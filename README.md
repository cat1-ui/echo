# Echo · 情感陪伴智能体

一个基于大模型的**情感陪伴聊天应用**。它不只是"一问一答的机器人"，而是一个能记住你、理解你情绪、主动关心你的陪伴者。

> 技术栈：Python · DeepSeek API · SQLite · Streamlit

---

## ✨ 功能特性

| 功能 | 说明 |
|------|------|
| 💬 多轮对话 | 流式输出（打字机效果），上下文连贯 |
| 🧠 长期记忆 | 自动从对话中提取用户信息（名字、喜好、目标等），7 类分类管理，跨会话持久 |
| 📝 对话摘要 | 聊满 20 条自动增量摘要，降低 token 成本、不丢早期信息 |
| 😊 情绪识别 | 识别用户情绪（开心/平静/难过/焦虑），并记录 |
| 📊 情绪洞察 | 情绪趋势曲线 + 分布饼图 + LLM 文字洞察 |
| 🗂️ 多会话 | 新建/切换/删除会话，对话历史隔离、记忆全局共享 |
| 🔧 工具调用 | Function Calling：算数、查时间、查天气（联网） |
| 🛡️ 安全兜底 | 检测自我伤害等极端信号，追加安全引导 |
| ⏰ 主动能力 | 开场主动问候 + 回复末尾引导式提问 + 时间感知 |

## 🏗️ 系统架构

```
用户
  ↓
Streamlit 界面 (app.py)
  ↓
ChatService 聊天服务（核心编排）
  ├── 取历史消息 ────────→ SQLite (messages)
  ├── 取长期记忆 ────────→ SQLite (memories)
  ├── 取对话摘要 ────────→ SQLite (summaries)
  ├── 拼 system prompt ──→ PromptBuilder（人设 + 时间 + 记忆 + 摘要）
  ├── Function Calling ───→ Tools（算数 / 时间 / 天气）
  ├── 流式生成回复 ──────→ DeepSeek API
  └── 后台异步 ──────────→ 记忆提取 / 情绪识别 / 摘要（不阻塞回复）
```

**设计要点：**
- **分层清晰**：界面层（app.py）/ 业务层（chat_service.py）/ 数据层（db.py）/ 工具层（tools.py）
- **流式 + 异步**：回复用生成器（yield）边生成边返回；记忆、情绪等副任务放后台线程，不阻塞主回复
- **降级容错**：所有副功能都 `try/except`，出错不影响主回复

## 🚀 快速上手

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置 API Key

复制 `.env.example` 为 `.env`，填入你的密钥：

```bash
DEEPSEEK_API_KEY=你的DeepSeek密钥
QWEATHER_KEY=你的和风天气密钥（可选，天气功能需要）
QWEATHER_HOST=你的和风天气专属域名（可选）
```

### 3. 运行

```bash
streamlit run app.py
```

浏览器打开 `http://localhost:8501` 即可开始聊天。

## 💡 技术亮点（面试可讲）

### 1. 大模型是"失忆的"，全靠 prompt 喂信息

模型本身不记得你是谁、不知道现在几点。解决方案是：每次对话，把**记忆、摘要、当前时间**重新拼进 system prompt。这是 LLM 应用开发的核心思想。

### 2. Function Calling：模型是"大脑"，工具是"手"

模型只会生成文字（JSON），不会真正"做事"。通过给模型一份"工具说明书"，让它在需要时"举手"返回 JSON，再由代码真正执行工具（算数、查天气），把结果喂回模型。

- 计算器用**白名单正则**校验表达式，拒绝任意代码执行（防代码注入）

### 3. 温度梯度设计（同一模型，不同任务不同温度）

| 任务 | 温度 | 原因 |
|------|------|------|
| 聊天 | 0.8 | 要活泼自然 |
| 情绪洞察 | 0.6 | 有温度但不啰嗦 |
| 摘要 | 0.3 | 要稳定 |
| 记忆/情绪提取 | 0.2 | 要精确 |
| 风险判断 | 0.1 | 要最保守 |

### 4. 安全兜底的"度"

只识别自我伤害等**极端信号**做安全引导，不把普通情绪低落误判为危险——避免过度干预，把握陪伴的"分寸感"。
